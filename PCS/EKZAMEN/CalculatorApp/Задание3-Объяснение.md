# Задание 3 — подробное объяснение всего кода

## Что требовалось по билету

Реализовать в **ASP.NET Core MVC** обработчик нажатия кнопки **Calculate** через атрибут **`[HttpPost]`**, который:

1. Принимает данные формы с полями **`Number1`** и **`Number2`**
2. Выполняет сложение через метод **`OnPostSum()`**
3. Сохраняет результат в **`ViewData["Result"]`**
4. Повторно отображает форму с результатом
5. Обрабатывает невалидные данные через **`ModelState.AddModelError()`**

---

### 1. Пользователь открывает сайт

```
Браузер → GET /Home/Index → HomeController.Index() → View Index.cshtml
```

### 2. Пользователь вводит 5 и 3, нажимает Calculate

```
Браузер → POST /Home/OnPostSum
Тело: Number1=5&Number2=3
→ [HttpPost] OnPostSum("5", "3")
→ TryParse успешен
→ ViewData["Result"] = 8
→ View Index.cshtml
```

На странице: форма с 5 и 3, строка `Result: 8`.

### 3. Пользователь вводит abc и 2

```
POST Number1=abc&Number2=2
→ TryParse(Number1) fails
→ ModelState.AddModelError("Number1", ...)
→ ModelState.IsValid == false
→ return View("Index") без Result
```

На странице: форма с `abc` и `2`, красная ошибка про Number1.

## Частые вопросы на зачёте/экзамене

### Чем GET отличается от POST здесь?

- **GET** `Index()` — только показать страницу.
- **POST** `OnPostSum()` — обработать отправленную форму. `[HttpPost]` запрещает вызывать `OnPostSum` через GET.

### Что такое Model Binding?

Автоматическое сопоставление полей HTTP-запроса (`Number1`, `Number2`) с параметрами метода `OnPostSum(string Number1, string Number2)` по **имени**.

### Зачем `string`, а не `int` в параметрах?

Чтобы самому проверить ввод и явно вызвать **`ModelState.AddModelError()`**, как требует задание. При `int` часть ошибок добавилась бы автоматически, без явного `AddModelError`.

### Чем ViewData отличается от ViewBag?

- **ViewData** — словарь `ViewDataDictionary`, ключи строки: `ViewData["Result"]`.
- **ViewBag** — обёртка над тем же словарём, синтаксис `ViewBag.Result`.
В задании указано именно **ViewData**.

### Что такое IActionResult?

«Контракт» результата action: View, Redirect, File, Json и т.д. `return View("Index")` возвращает объект, который pipeline MVC превратит в HTML.

### Что делает `return View("Index")`?

Ищет файл `Views/Home/Index.cshtml` (контроллер `Home` + имя `"Index"`), рендерит Razor → HTML → отправляет клиенту.

### Почему `asp-action="OnPostSum"`, а не `action="/Home/OnPostSum"`?

Tag Helper генерирует правильный URL с учётом маршрутов и может добавить antiforgery (если включён). Короче и безопаснее для MVC.

### Что такое Tag Helper?

Razor-расширение HTML-атрибутов (`asp-*`), которое на сервере превращается в корректный HTML/URL. Подключается в `_ViewImports.cshtml`.

### Когда `ModelState.IsValid` становится false?

Когда вызван `AddModelError`, или есть ошибки привязки модели, или не прошла серверная/клиентская валидация.

### Можно ли было назвать метод `Calculate`?

По **этому** билету — **нет**, нужно именно **`OnPostSum()`**. Имя метода связано с `asp-action="OnPostSum"`.

## Краткая шпаргалка «одним абзацем»

Приложение ASP.NET Core MVC: `Program.cs` регистрирует MVC и маршрут `{controller}/{action}`. `HomeController.Index()` по GET показывает форму. Кнопка **Calculate** отправляет POST на `OnPostSum` с полями **Number1** и **Number2**. Метод с атрибутом **`[HttpPost]`** парсит числа; при ошибке вызывает **`ModelState.AddModelError()`** и снова возвращает **`View("Index")`**; при успехе пишет сумму в **`ViewData["Result"]`** и снова показывает ту же форму, где Razor выводит результат и ошибки.
