# Практическое занятие №5 — «Интерактивная система управления производством»

ASP.NET Core MVC + **Entity Framework Core 8** + **REST API** + SQLite.

Полнофункциональная система учёта материалов, каталога изделий, планирования заказов и управления производственными линиями с автоматическим расчётом сроков и контролем сырья.

## Запуск

```powershell
cd .\PCS\P_5\ProductionSystem
dotnet run
```

Откройте адрес из консоли (обычно `https://localhost:7xxx`). **Главная страница — дашборд** (`/`).

## Панели интерфейса

| Панель | URL | Функции |
|--------|-----|---------|
| **Дашборд** | `/` | KPI (материалы, низкий запас, продукты, заказы, линии), последние заказы, быстрые ссылки |
| **Материалы** | `/Materials` | таблица склада, подсветка низкого запаса, добавление, **редактирование**, **Пополнить** |
| **Продукты** | `/Products` | фильтр по категории, поиск, создание и **редактирование** с привязкой материалов, валидация JSON |
| **Заказы** | `/Orders` | фильтры по статусу, прогресс-бар, **Детали** заказа, создание с live-расчётом, **Запустить**, **Отменить** |
| **Линии** | `/Lines` | статус, прогресс, **быстрый запуск** заказа, эффективность, расписание, перенос сроков |
| **API** | `/Home/ApiDocs` | таблица REST-эндпоинтов |

### Дашборд

- Сводные карточки: количество материалов, позиций с низким запасом, продуктов, активных и текущих заказов, свободных линий.
- Таблица последних 5 заказов со ссылками на детали.
- Блок «Требуют пополнения» для материалов ниже минимального запаса.

### Материалы

- Жёлтая подсветка строк, где `Quantity < MinimalStock`.
- Баннер-предупреждение при наличии таких позиций.
- Форма редактирования по ссылке «Изменить» (`?editId=`).
- Быстрое пополнение склада без перехода на другую страницу.

### Продукты

- Фильтрация по категории и поиск по названию.
- Создание изделия с выбором материалов и количества на 1 шт.
- Редактирование существующего продукта (время, категория, рецептура).
- Поле `Specifications` проверяется на валидный JSON.

### Заказы

- Фильтры: все / активные / ожидают / в работе / завершены.
- Колонка прогресса для заказов «В работе».
- Страница **Детали** (`/Orders/Details/{id}`): план материалов, сроки, линия.
- Форма создания с **live-расчётом** через `/Orders/Calculate`:
  - время производства в минутах;
  - дата окончания с учётом выбранной даты начала;
  - проверка достаточности материалов с перечислением недостающих позиций.

### Линии

- Карточки линий: статус (работает / остановлена), текущий заказ, ползунок прогресса.
- **Быстрый запуск**: на свободной активной линии — выбор продукта и количества → создание и немедленный старт заказа.
- Запуск ожидающего заказа из выпадающего списка.
- Настройка коэффициента эффективности (0.5–2.0) с пересчётом сроков pending-заказов.
- Расписание и перенос даты начала заказа.

## REST API (по заданию)

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/api/materials?low_stock=true` | Материалы с низким запасом |
| POST | `/api/materials` | `{name, quantity, unit, min_stock}` |
| PUT | `/api/materials/{id}/stock` | `{amount}` — пополнение |
| GET | `/api/products?category=...` | Список продуктов |
| GET | `/api/products/{id}/materials` | Рецептура продукта |
| POST | `/api/products` | `{name, prod_time, category}` |
| GET | `/api/lines?available=true` | Доступные линии |
| PUT | `/api/lines/{id}/status` | `{status}` |
| GET | `/api/lines/{id}/schedule` | Расписание линии |
| GET | `/api/orders?status=active&date=today` | Фильтр заказов |
| POST | `/api/orders` | `{product_id, quantity, line_id}` |
| PUT | `/api/orders/{id}/progress` | `{percent}` |
| GET | `/api/orders/{id}/details` | Детали заказа |
| POST | `/api/calculate/production` | `{product_id, quantity}` — расчёт времени |

Полная таблица также доступна в UI: **API → `/Home/ApiDocs`**.

## Модели БД

- `Product` — изделие (время на единицу, категория, JSON-характеристики)
- `Material` — сырьё (количество, ед. изм., минимальный запас)
- `ProductMaterial` — рецептура (сколько материала на 1 изделие)
- `ProductionLine` — линия (статус, коэфф. эффективности, текущий заказ)
- `WorkOrder` — заказ (количество, статус, прогресс %, сроки)

## Бизнес-логика (`ProductionService`)

**Время производства:**

```text
(Количество × ВремяНаЕдиницу) / КоэффЭффективности
```

**Контроль материалов:**

- при создании и запуске заказа проверяется достаточность сырья;
- при запуске материалы списываются со склада;
- при отмене или остановке линии материалы возвращаются на склад;
- при изменении эффективности линии или параметров продукта пересчитываются сроки ожидающих заказов.

**Дополнительно:**

- `CreateAndStartOnLineAsync` — создание и немедленный запуск заказа на линии;
- `UpdateMaterialAsync` / `UpdateProductAsync` — редактирование с сохранением целостности;
- `RescheduleWorkOrderAsync` — перенос даты начала;
- `UpdateProgressAsync` — обновление процента выполнения (0–100).

## Начальные данные (seed)

- 5 материалов (микросхемы — ниже минимального запаса для демонстрации предупреждений)
- 3 продукта с рецептурами
- 3 производственные линии (разная эффективность)
- 2 заказа в статусе Pending

## Типовой сценарий проверки

1. Откройте дашборд — убедитесь, что KPI и предупреждение о микросхемах отображаются.
2. **Материалы** → пополните микросхемы → строка перестанет быть жёлтой.
3. **Заказы** → создайте заказ с live-расчётом → проверьте сообщения о материалах.
4. **Линии** → быстрый запуск на свободной линии или запуск pending-заказа.
5. Обновите прогресс ползунком → заказ движется к завершению.
6. Проверьте REST: `GET /api/orders?status=active`.
